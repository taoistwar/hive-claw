## manifest schema 迁移完成（第四轮）

### 新模块 `crates/hivegui/src/datasource/plugin_manifest.rs`

### 关键事实（重要架构发现）
1. **hiveweb 的 `registered_imports()`（capability 名）模型与实际 host_call 架构脱节**：实际 extism 插件 import 的是 `extism:host/user.host_call`（单一 host_call，`invoker.rs` 用 `with_function("host_call", ...)` 注册），capability 通过 host_call JSON envelope 传递，**不是** WASM import 名。所以 `scan_wasm_imports` 的 `allowed`（capability 名）参数对合法 extism 插件永远不生效（都被 `extism:host/` 前缀放行）。这是一个遗留的、需产品决策的验证模型问题。
2. **hiveweb host_call module 是 `extism:host/user`**（extism PDK 命名空间），而共享契约 `HOST_CALL_MODULE = "env"`。二者不一致，需统一（改 extism 注册 module 或确认 `extism:host/user` 合法）。
3. **hiveweb 错误码与共享 `StableErrorKind` 分歧**：hiveweb `capability.rs` 用 4000（invalid envelope）、4292（rate limited）、5031（plugin system disabled）、5007（model preset unknown），均不在共享表（4001/4030/4045/4081/4990/5000/5004/5011/5012/5013）。完整统一 `capability.rs` 需调和这些 API 契约错误码。
