# HiveGUI 管理界面主题样式统一设计

日期：2026-07-15  
状态：已确认

## 背景

HiveGUI 的管理页面由多个独立视图逐步实现，按钮和列表样式存在重复代码与硬编码颜色。分类页面使用蓝色主操作、绿色编辑、红色删除和灰色取消；全局配置与 LLM 配置仍使用紫色主操作，数据管理的部分按钮直接依赖主题主色。多个列表还固定使用白色行背景和浅灰色表头，在深色主题下无法正确适配。

本次改造以分类页面的列表结构和操作语义为视觉基准，但将颜色来源改为 GPUI Component 的主题令牌，使所有管理页面在不同主题下保持统一并具备足够对比度。

## 目标

1. 所有管理页面使用同一套主题感知的按钮语义。
2. 默认浅色主题下，新增、保存、搜索等主操作保持蓝色，不再显示为紫色。
3. 所有管理列表采用分类页面的结构、字号、间距、边框和操作区规则。
4. 切换深浅主题后，按钮、表头、数据行、边框和文字颜色立即随主题更新。
5. 保留各页面现有字段、数据加载、分页、弹窗和 CRUD 行为。

## 非目标

- 不重写 Store、数据库访问或实体模型。
- 不引入通用数据表格的数据抽象，不改变各页面的列定义与宽度。
- 不改变顶部导航、侧边栏或普通内容卡片的布局。
- 不把警告、成功、危险等具有明确语义的操作全部改成同一种蓝色。

## 方案选择

采用“共享主题样式层，保留页面渲染逻辑”的方案。

未采用以下方案：

- 通用 `ManagementTable`：能够消除更多重复代码，但需要重写各页面的表格、分页和事件绑定，风险与本次视觉改造不匹配。
- 全面迁移到 GPUI Component Table：主题能力更完整，但会扩大交互和状态管理改动。

共享样式层只负责语义颜色与视觉尺寸，页面仍负责列、数据和事件，因此可以逐页迁移并独立验证。

## 主题样式层

新增 `crates/hivegui/src/ui/management_style.rs`，提供以下概念：

### 操作语义

定义 `ActionRole`，并从当前活动主题生成对应颜色：

| 角色 | 用途 | 主题令牌 |
| --- | --- | --- |
| `Main` | 新增、保存、搜索、启用分页、当前选项 | `button_info`、`button_info_hover`、`button_info_active`、`button_info_foreground` |
| `Edit` | 编辑操作 | `button_success`、`button_success_hover`、`button_success_active`、`button_success_foreground` |
| `Delete` | 删除及不可逆操作 | `button_danger`、`button_danger_hover`、`button_danger_active`、`button_danger_foreground` |
| `Warning` | 导入、覆盖等风险操作 | `button_warning`、`button_warning_hover`、`button_warning_active`、`button_warning_foreground` |
| `Neutral` | 取消、关闭、刷新等次要操作 | `button_secondary`、`button_secondary_hover`、`button_secondary_active`、`button_secondary_foreground` |
| `Disabled` | 禁用操作 | `muted`、`muted_foreground` |

主操作刻意使用 `button_info`，而不是 `button_primary`。当前默认主题的 `button_primary` 是紫色；`button_info` 提供与分类页面一致的蓝色语义，同时仍由每个主题提供适配的前景色、悬停色和按下色。

样式在每次 `render` 时从 `cx.theme()` 读取，不缓存到视图实体中。因此主题切换触发重绘后，界面会立即采用新主题颜色。

### 列表语义

定义 `ManagementListStyle`，从活动主题读取：

- 容器边框和分隔线：`border`
- 表头背景：`list_head`
- 数据行背景：`list`
- 可交互行悬停背景：`list_hover`
- 主文字：`foreground`
- 次要文字和空状态：`muted_foreground`
- 标签及弱强调背景：`muted`

主题提供的前景色与语义按钮色必须成对使用，禁止继续固定使用白色文字或白色行背景。

### 统一尺寸

共享模块提供管理列表尺寸常量或样式函数：

- 容器：1 px 边框、4 px 圆角、裁切溢出。
- 表头单元格：水平 8 px、垂直 8 px、12 px 粗体。
- 数据单元格：水平 8 px、垂直 6 px；普通文字 12 px，名称等主要字段可用 13 px 中等字重。
- 操作区：按钮间距 4 px。
- 行内操作按钮：水平 8 px、垂直 3 px、3 px 圆角、11 px 字号。
- 页面主操作：水平 12 px、垂直 6 px、4 px 圆角、13 px 字号。
- 弹窗操作：水平 16 px、垂直 8 px、6 px 圆角、13 px 字号。

共享代码可以返回按钮颜色快照和预设样式的 `Div`，但不接管页面事件处理。调用方继续附加自己的元素 ID、点击事件、禁用条件和调试选择器。

## 列表结构

所有普通管理列表统一采用以下结构：

1. 带圆角和边框的列表容器。
2. 单独的表头行，使用 `list_head`。
3. 连续的数据行，使用 `list`，行间使用底部分隔线，不再使用 LLM 当前的卡片间隙。
4. 列按照各页面业务需要保持固定宽度或弹性宽度。
5. 最右侧保留操作列，编辑和删除使用统一的语义按钮。
6. 空数据时继续显示页面原有空状态，但颜色和间距来自共享样式。
7. 分页区保持页面原有数据逻辑，启用、禁用和当前页状态使用共享操作语义。

数据库表查看器保留多标签、列选择、单元格编辑等专用交互，只迁移表头、行、边框、分页和操作颜色。数据源树保留树形结构，只使用共享主题颜色，不强制改成二维表格。

## 迁移范围

### 标准 CRUD 管理页面

- 分类
- 标签
- 全局配置
- 能力
- 函数
- 技能
- 工具
- 工作流
- 插件
- Agent

### 专用管理页面

- LLM 的 Model、Preset、Provider 列表与表单
- 数据源管理及数据源表单
- 数据库表查看器
- 数据管理页面的导出、导入按钮

页面背景、弹窗背景及输入框继续使用已有主题组件或对应主题令牌；本次不改变数据流。

## 行为与数据流

共享样式层不持有状态。页面渲染流程为：

1. 页面读取当前实体数据和活动主题。
2. 共享样式层从主题生成按钮与列表颜色。
3. 页面按现有列和数据构造元素，应用共享样式。
4. 点击事件继续调用页面原有新增、编辑、删除、搜索或分页方法。
5. 切换主题后 GPUI 通知重绘，步骤 2 重新计算颜色。

数据加载失败、保存失败、删除确认和表单校验逻辑保持不变。错误信息使用主题的 `danger`，成功信息使用 `success`，警告信息使用 `warning`。

## 实施顺序

1. 先用测试定义按钮角色与列表主题映射。
2. 新增共享管理样式模块。
3. 迁移分类页面，使视觉基准本身先具备主题适配能力。
4. 迁移结构与分类相近的标准 CRUD 页面。
5. 迁移全局配置和 LLM 页面，清除紫色主操作及 LLM 卡片式行。
6. 迁移数据源、数据库表查看器和数据管理按钮。
7. 扫描管理页面剩余的旧紫色及列表硬编码浅色，并逐项核对用途。

## 测试与验收

### 自动测试

- 单元测试验证每个 `ActionRole` 使用正确的主题令牌，尤其验证 `Main` 使用 `button_info` 而非 `button_primary`。
- 单元测试验证列表样式使用 `list_head`、`list`、`border`、`foreground` 和 `muted_foreground`。
- 视觉布局测试验证代表性页面的表头、首行、操作列和分页区均位于列表容器内，且行高、内边距和操作按钮尺寸符合共享规则。
- LLM 回归测试继续验证 Model 和 Provider 显示 ID，并增加标准列表结构断言。
- 运行 `cargo test -p hivegui`，确保所有单元与集成测试通过。

### 人工视觉检查

至少在 Default Light 和一个深色主题下检查：

- 主操作是主题适配的蓝色，文字清晰。
- 编辑、删除、警告和次要操作的语义颜色正确。
- 表头、数据行、边框、空状态和分页在深浅主题下均可辨识。
- 分类、全局配置、LLM 与至少一个其他 CRUD 页面列表结构一致。
- 弹窗、下拉菜单及嵌套滚动行为没有回归。

## 风险与控制

- **主题令牌在不同主题中的对比度差异**：始终使用令牌配套的 foreground、hover 和 active 颜色，不自行混用固定白色。
- **一次迁移页面较多**：按页面组逐步迁移，每组完成后运行目标测试。
- **通用抽象过度**：共享视觉语义和尺寸，不抽象实体数据、列或事件。
- **专用表格交互回归**：数据库表查看器只替换样式来源，不调整缓存、选择、编辑或分页状态机。

## 验收标准

1. 全局配置页面不再出现旧紫色主操作。
2. 所有管理页面的主操作、编辑、删除、警告、次要和禁用操作遵循统一语义。
3. 所有管理列表在结构与尺寸上与分类列表一致，专用树形和数据库表格仅保留必要差异。
4. Default Light 与深色主题下均不存在固定白底、低对比文字或不可辨识按钮。
5. 主题切换后无需重启即可更新按钮和列表颜色。
6. 完整 HiveGUI 测试通过，原有 CRUD、分页、弹窗和滚动行为不变。
