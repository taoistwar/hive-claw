## 【关键架构发现】受控存储 PluginStore 从未接入生产路径（2026-08-19 第八轮）

### 事实（已核实）
1. **受控存储 `PluginStore`（T077/T078 完整实现 + 12 测试）只被测试引用**，生产代码里 `grep PluginStore crates/hivegui/src` 仅命中定义文件 + `PluginExecutor.store` 字段（execute 系列是静态方法，不走 `self.store`）。
2. **两套存储布局并存且不一致**：
   - 生产 UI 导入 `save_wasm_locally`（`plugin_view.rs`）+ execute `FunctionTestExecutor`：`base_dir/plugins/{id}/plugin.wasm`（数字 `id` + 固定 `plugin.wasm`）。
   - 受控存储 `PluginStore`：`plugin_root/{identifier}/{version}.wasm`（字符串 `identifier` + `{version}.wasm`）。
   - 逻辑键 `s3_key`：`plugins/{identifier}/{version}.wasm`（与 PluginStore 布局一致，与生产文件布局 `{id}/plugin.wasm` 不一致）。
3. `Store`（store.rs）有 `plugin_root` 字段但**无公开 getter**；生产 UI 用 `Store::default_db_path()`（`~/.local/share/hivegui`）作 `base_dir`，从未创建 `PluginStore`。

### 结论
- 「execute 复用 `read_verified_artifact`」的真实障碍不是 extism，而是**布局断点**：execute 用 `{id}/plugin.wasm`，`read_verified_artifact` 用 `{identifier}/{version}.wasm`，两者无法直接对接。
- 打通需要**大集成**（需产品决策）：
  1. 布局统一：`{id}/plugin.wasm` → `{identifier}/{version}.wasm`（存量文件迁移或兼容读取）。
  2. `Store` 暴露 `plugin_root()` getter。
  3. UI 导入迁移：`save_wasm_locally` → `PluginStore::install`（六态状态机）。
  4. execute 迁移：`FunctionTestExecutor` 改调 `read_verified_artifact`。

## 插件制品布局全量统一为 `{identifier}/{version}/{id}/plugin.wasm`（2026-08-19 第九轮）

### 背景

### 统一助手（`crates/hivegui/src/datasource/entity_store.rs`，`Plugin` impl）
- `artifact_dir(identifier, version, id) -> PathBuf` = `{identifier}/{version}/{id}`。
- `artifact_key(identifier, version, id) -> String` = `{identifier}/{version}/{id}/plugin.wasm`（`s3_key` 单一事实来源）。
- `artifact_wasm_path(base_dir, identifier, version, id)` = `{base_dir}/plugins/{identifier}/{version}/{id}/plugin.wasm`。
- `wasm_path(&self, base_dir)` 改为走 `artifact_wasm_path`；`ensure_plugin_dir(base_dir, identifier, version, id)` 签名 + 布局同步改。
- 新增 `set_artifact_key(pool, id, s3_key)`（create 后回填，因 id 只有 INSERT 后才知道）。

### 各调用点改造
- `plugin_view.rs`：`save_wasm_locally(base_dir, identifier, version, id, src)`；`save()` 的 s3_key 改为 `artifact_key`（create 分支 INSERT 后回填、edit 分支用 `editing_id`、keep 分支保留原始）；`delete()` 先 `Plugin::get` 拿 identifier/version 再按 `artifact_dir` 删目录。
- `function_test_executor.rs`：`execute`/`execute_with_capabilities` 增加 `plugin_identifier`/`plugin_version` 参数（旧测试入口，无 DB 只能显式传）；`execute_with_verification` 改为先 `Plugin::get` 再 `plugin.wasm_path(base_dir)`。
- `plugin_store.rs`：`publish_artifact`/`resolve_artifact_path`/`read_verified_artifact`/`read_artifact_for_test` 全部加 `id` 参数；`artifact_for` 传 `id`。

### PluginStore::install 的 id-before-publish 耐久性难题（关键）
- 原顺序 publish → INSERT（schema CHECK：create 操作的 `prepared/staged/published` 态要求 `plugin_id IS NULL`），但新布局 publish 需要 id。
- 解法：**soft-deleted 占位行**——先 `INSERT ... deleted_at = now` 拿 id（行不可见），publish `{identifier}/{version}/{id}/plugin.wasm`，再 `UPDATE ... deleted_at = NULL, s3_key = ...` 转 live，最后 referenced → done。崩溃窗口（INSERT→publish、publish→un-delete）只留 soft-deleted 孤儿（GC 清理），不会出现「无制品的 live 行」。
- `recover_interrupted_operations` 逻辑不变（`operation_artifact_path` 仍返回 None，制品留给 GC），仅更新 doc 注释。
