## 查看执行记录弹窗：点击内容会关闭 + 无法选文字

- 现象：`view_modal` 中点击弹窗内容任意位置都会关闭整个弹窗（影响操作），且 GPUI 0.2 的普通 `div` 文本**不可拖选**，用户无法复制/选取记录内容。
- 根因：原 panel 上的 `.on_mouse_down(MouseButton::Left, |_, _, _| {})` 是 bubble 阶段空回调，无法阻止事件冒泡到外层 overlay 的 `on_mouse_down`（关闭逻辑）。GPUI 0.2 的 `div` 文本没有原生 `selectable()` 能力（已核对 `crates/gpui/src/elements/div.rs`，无 selectable API；`Text` 元素也仅 InteractiveText 支持交互选段）。
- 改动（`crates/hivegui/src/ui/prompt_debugger.rs`）：
  1. 在 panel（子容器，含标题栏+内容）上改挂 **`capture_any_mouse_down(|_, _, cx| cx.stop_propagation())`**，在 capture 阶段拦截，阻止冒泡到 overlay 关闭逻辑。点击内容不再关闭弹窗。
  2. 新增 `format_records_for_copy(records)`：将单条/对比记录的「模型/参数/消息/工具/结果」拼为可读纯文本。
  3. 标题栏「关闭」按钮旁新增「复制」按钮（IconName::Copy + "复制" 文字），`on_mouse_down` 时 `cx.write_to_clipboard(ClipboardItem::new_string(text))` 写入剪贴板，并 `stop_propagation()`。弥补 GPUI 0.2 文本不可拖选的限制，满足"取走/选择记录文字"的诉求。
- 注意：GPUI 0.2 没有 `div.tooltip()` 所需的 `StatefulInteractiveElement`/`InteractiveElement` trait 自动在 `use gpui::*;` 作用域（sidebar_nav 靠 `use gpui::prelude::*;` 引入）。为避坑，复制按钮未用 tooltip，直接以图标+文字呈现。
- 验证：`cargo check -p hivegui` 0 error、`cargo test --lib -p hivegui` 102 项通过、`cargo clippy -p hivegui` 无本文件相关 warning。
